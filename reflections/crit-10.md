# Crit 10 reflection

Completed after the scheduled session, since I'd missed it.

**Breakthrough.** Claude had already checked, from the infrastructure side, that the database sat on the mounted volume and that its row counts survived a redeploy. I asked what reopening an old link myself could possibly add to that — the database check seemed to already answer the question. The distinction I hadn't separated out until then: a correct database is not the same claim as a returning participant actually being able to see their result. So I reopened a room whose outcome I already knew, in the original browser, after the redeploy, and saw the same two options under the same headings, with no invitation to submit again — recorded in [f084144](https://github.com/comp4020-agentic-coding-studio/comp4020-final-nzuuu9/commit/f084144d0209891accdf407d16f665d5f8ff61bb). That's evidence about the participant's experience, which the database check alone couldn't give me.

**What it changed.** I'm more alert to the gap between "the backing data is correct" and "the person using it can actually get at it" — two different claims, only one checkable by reading rows in a table.
