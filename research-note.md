# Why I would still open the room myself

After Claude redeployed my group decision app, it reported that the database still contained three rooms and seven submissions. It also asked me to reopen an old room in my browser. I asked what that could possibly add. I now have two questions for an agent that says a change is finished. What evidence would convince me that a user can do what we promised? And do I understand the change well enough to investigate if that promise breaks tomorrow? I would still open the room myself, even if the agent could show me its own browser run. Those two questions explain why.

There is a strong case for delegating verification. In SWE-bench, Jimenez and colleagues evaluate a proposed repair against a real repository. A successful patch must make the tests associated with the issue pass while preserving the passing results of selected existing tests. That second condition matters. An agent could fix the bug I described and break something I had stopped thinking about. A repeatable suite can catch that regression on every attempt. In my app, for example, adding a live submission count should leave the other participant's unfinished choices intact. Remembering to try that interaction after every edit would be a poor substitute for recording the expectation once. [Jimenez et al., 2024][swe]

The difficulty is deciding which expectation deserves to be recorded. OpenAI's later audit of SWE-bench Verified describes a task asking for Python type hints to appear in a UML diagram. The test imported a helper called `get_annotation`. An implementation could produce the requested diagram and still fail because its author had organised the code differently. The audit examined a subset of frequently failed tasks, so this example cannot tell us how often ordinary project tests make that mistake. It does expose a weakness in treating a test result as a verdict on a requirement. Adding a hidden requirement can make an evaluation stricter while making its verdict less accurate. I would specify what the diagram must display and leave the helper's name open, unless another caller actually relies on that name. [OpenAI, 2026][audit]

Willison offers a practical extension to automated suites. A coding agent can also operate a running application through a browser and inspect what appears on screen. That raises a fair objection to my position. If Claude reopens the deployed room using the original participant's browser profile and checks the expected result, its run supplies evidence about that journey. Clicking the same link myself does not automatically strengthen the test. What I gain from doing it once is the chance to check my own understanding. In this case I had to explain why the original profile mattered, which result I expected and why the page should offer no second submission. If the rows survived but the room asked me to vote again, I would know to investigate how the returning browser was recognised. A click alone would never have taught me that. [Willison, *Agentic manual testing*][willison]

My own familiarity also has a limit. When I showed the app to my housemate, his first question was what it was for. I had been looking at the same question and options throughout development, so I already knew why anyone would mark them privately. After I explained the purpose, he used the controls easily. His question revealed an assumption shared by the person who designed the interface and the person who tested it: in this case, both were me. An unexplained link given to another newcomer would provide better evidence about whether the introduction works.

I would therefore ask an agent to report what changed, which boundary cases it exercised, what it observed and what remains unchecked. I would keep repeatable regression checks automated and personally follow the main user journey when a change affects a promise I will have to maintain. The decision to accept the work stays with the developer. That responsibility includes recognising when the next person who needs to try the software is someone who has never seen it before.
